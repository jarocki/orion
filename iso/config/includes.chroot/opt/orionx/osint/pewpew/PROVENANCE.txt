Why the upstream code is NOT vendored
-------------------------------------
Two reasons, both disqualifying for this product:

  1. It cannot run offline. At the pinned commit index.html loads d3 v3,
     d3.geo.projection, topojson v1 and datamaps from three different CDNs,
     jQuery from code.jquery.com, Font Awesome from cdnjs, and two Google
     Fonts families. On a disconnected deck the page renders an empty black
     rectangle. Vendoring the dependency set would mean adding d3 v3 (2015)
     and Datamaps 0.5.9 (2016) — two abandoned libraries — to an
     incident-response image.

  2. Its data model is the thing this map must not do. Upstream *invents*
     attacks: `random_mode`, `china_mode`, `dprk_mode`, `bad_day`, and by
     default a statistical model that picks source countries and places them
     at country centroids. That is a demo. On a tool an operator uses to
     decide where an intrusion came from, invented coordinates are a defect,
     not a flourish (docs/RESILIENCE.md, rule 8 and the paragraph above it).

So orionx-pewpew is an independent implementation of the *idea* — tracers
converging on the deck, with sound — written against Orion-X's own event bus,
with no third-party JavaScript at all and no position it cannot source. The
debt owed upstream is the concept and the sound, and it is acknowledged in
the page footer, in the About panel, and here.

Geolocation
-----------
No GeoIP database ships on the ISO. See ../GEOIP.txt for why, what the map
shows without one, and the exact command that adds country/ASN labels.

GODSEYE on Orion-X — every host name present in the bundle that ships
=====================================================================
DEC-PHASE12-045 · /opt/orionx/osint/godseye/

Read this before you open GODSEYE on a network you do not control.

GODSEYE is a live-API application. It has no offline mode and no cached
world: the globe's base imagery, every aircraft, every satellite pass, every
earthquake and every camera arrives over the internet at the moment you look
at it. Opening it announces this deck — its address, and the subject of your
interest — to between a handful and a few dozen third parties, depending on
which layers you enable.

That is not a reason never to use it. It is a reason to know the list.

How this list is kept true
--------------------------
The block between the INVENTORY markers at the bottom is *generated* from the
bytes under ./app/ by `scripts/osint/godseye_hosts.py`. It is not a summary
and not a memory: it is every syntactically valid host name appearing in a
URL literal anywhere in the shipped bundle, including inside Cesium.js, the
feed manifests and the compiled application chunk.

`tests/unit/test_godseye.sh` re-derives it and fails if it has drifted. So
re-vendoring GODSEYE cannot quietly add a host — the suite goes red and a
human has to classify the new name in the sections below.

The sections below are the part a human wrote. They are a judgement about
*when* each host is contacted, and they are signed as one. Section G is
defined as the complement: anything in the inventory that A-F do not name is
a string in the bytes that nothing requests — documentation links, licence
URLs, XML namespaces, Cesium's own source comments and attribution.


A. CONTACTED THE MOMENT THE GLOBE OPENS
---------------------------------------
Unavoidable. There is no GODSEYE without these.

  server.arcgisonline.com     Esri World Imagery raster tiles — the map
  services.arcgisonline.com   Esri World Imagery (high-detail upgrade) and
                              the country/city label reference overlays
  terrain.reearth.land        Cesium quantized-mesh terrain

  With these unreachable the globe is a featureless dark ellipsoid. That is
  the state this deck's gate exists to refuse to show you.

  CesiumJS does ship a 43-tile offline Natural Earth II basemap (zoom 0-2) at
  app/cesium/Assets/Textures/NaturalEarthII/, and a reviewer will find it.
  GODSEYE never instantiates it: src/components/Globe.jsx constructs the
  Viewer with `baseLayer` set to the Esri provider above and
  `baseLayerPicker: false`, so there is no code path and no control that
  reaches those tiles. They do not rescue the offline case today. Wiring
  them in as an offline fallback would be a real improvement and is recorded
  as a follow-up rather than claimed here.

C. RELAYS — READ THIS ONE TWICE
-------------------------------
  api.allorigins.win          anonymous public CORS relay
  r.jina.ai                   anonymous public reader/proxy

Roughly fifteen of GODSEYE's feeds are not fetched from their origin. They
are fetched *through* one of these two relays, because the origin does not
send CORS headers a browser will accept. Concretely:

  - the relay operator sees this deck's public address;
  - the relay operator sees the full target URL, which is the question you
    are asking — which ADS-B box, which METAR bounding box, which fire
    region;
  - the relay operator returns the answer, and can change it. Nothing in
    GODSEYE authenticates what comes back.

  - `r.jina.ai` is additionally used in the form `https://r.jina.ai/http://...`:
    the leg from the relay to the origin is plaintext HTTP.

This is an ordinary engineering compromise for a public web app and an
unusual thing to accept on an incident-response deck. It is the single
strongest argument against enabling GODSEYE on a sensitive engagement, and it
is why `orionx-osint` will not serve this bundle at a raised posture.


D. CONTACTED ONLY WHEN YOU OPEN A SPECIFIC CAMERA OR STATION
------------------------------------------------------------
./app/manifests/cctv-verified.json carries several thousand curated public
camera entries and the radio station list carries several hundred streams.
Their hosts are in the inventory below and are *not* listed here one by one,
because none of them is contacted until you click that entry. They include
commercial camera platforms (worldcams.tv, earthcam.net, ivideon,
rhombussystems, angelcam, nest/dropcam), municipal DOT stream endpoints, CDN
edges and broadcaster audio streams, across many jurisdictions including
ones you may not wish to transit.

A single click here is a direct TLS connection from this deck to that
operator. Treat each one as a deliberate act.

                              unreachable twice over

GODSEYE reads its keys from Vite build-time environment variables
(`VITE_*`). This bundle was built with none of them set, so the key values
are compiled out: the code paths above cannot run and the hosts cannot be
reached. No key is present in this tree, and none can be added by editing a
file on the deck — a key would have to be baked in at build time, which
would publish it in cleartext inside a distributed ISO. Orion-X will not do
that. See PROVENANCE.txt for the build command.

CesiumJS ships its own public demo ion token inside app/cesium/Cesium.js.
It is upstream's token, not a secret, not Orion-X's, and nothing in this
build requests an ion-backed asset.


F. DEAD IN THIS BUILD — NO NODE BACKEND
---------------------------------------
Upstream GODSEYE ships a Node service (`server/`) that proxies five route
families the browser cannot call directly. Orion-X runs no Node at runtime,
so these routes do not exist here and the layers that depend on them cannot
work even with a perfect network:

  /api/flights        aircraft via the backend proxy
  /api/cctv/*         camera source index and frame grabs
  /api/radio/*        station list and click-through
  /api/traffic/*      flow tiles and status
  /api/overpass       Overpass queries via the backend

`osint_server.py` answers each of them with HTTP 501 and a JSON body that
says so by name, rather than a bare 404 the application would render as an
empty layer. Some aircraft and camera data still arrives through the direct
browser paths in section B; the proxied paths do not.

Everything in the inventory below that sections A-F do not name. These are
documentation links, licence URLs, XML namespaces, academic references and

because an audit that hides what it judged irrelevant is not an audit.
